## 五、关键风险

按「发生后是否直接导致交不上」排序。

### R1 · 知乎 CLI 能否在公网服务器工作〔风险已大幅降低〕

**已验证（11-23）**：`ZHIHU_ACCESS_SECRET` 环境变量方式可正常检索（`Code:0 success`），
且环境变量优先于 keychain（`environment_shadows_keychain=true`）。服务器无需 keychain。

**剩余未知**：Linux 版 CLI 二进制能否安装。官方 `setup.sh` 支持 `linux-amd64`，
风险不大，但需实测。可用 Docker 验证，不必等租机器。

**这仍是 P5 的前置条件**，但不构成阻断风险。

### R2 · 部署与 HTTPS

前端若是 https 页面、后端是 http，浏览器会拦截请求。**部署时前后端必须同协议**，或都给 https。

### R3 · 模型依赖〔新增〕

结论摘要依赖 DeepSeek。Key 失效、额度耗尽、服务抖动都会让质量掉一档。
代码里已做降级（失败退回关键词抽取），但**降级后的结论明显变差**，演示前需预热确认。

### R4 · 密钥泄露

官方检查第 6 条：Key / Secret / Token 不得出现在源码、前端响应、日志、截图、视频。

**现状**：`.env` 已被 `.gitignore` 排除，仓库里只有 `.env.example`。
**待办**：提交前全仓库搜一次 `sk-`、`secret`、`token`；DeepSeek Key 曾出现在聊天记录中，**建议重新生成**。

### R5 · 演示不可复现

同一次检索两次结果可能不同。已用本地缓存缓解（24 小时），但**演示前必须预热**。

### R6 · 额度

知乎搜索 5000 次、直答 100 次、模型调用按量计费。开发期依赖缓存，不要反复真调。

### R7 · 把 Mock 说成成品

官方检查第 9 条。降级数据可用于演示，但界面必须标「演示数据」，计划书里也不能含糊。

## 六、四维评分策略

初审权重：**AI 场景价值 40% / 创新度 25% / 完成度 25% / 产品体验与设计感 10%**。

### 维度一 · AI 场景价值（40%）

**评委在判断**：解决的是不是真实、够痛、非它不可的问题。

| 高分标准 | 已有的证据 |
|---|---|
| 痛点可验证 | 「哪个好」10 条里 8 条是导购；赞 1990 的是最典型的广告，真有用的只有 1 个赞 |
| 场景明确 | 两千元档家电决策、装修避坑：花错钱会后悔、软文最密、交叉比价最费时 |
| AI 不可替代 | 「哪个好」翻译成「缺点/耗材/装得下吗」，软文比例 40% → 2.5%，人做要 30 分钟 |
| 30 秒可感 | 结论句 ≥24px，第一屏可见 |

**验收检查项**

- [ ] 不懂技术的人 60 秒内能说出「这产品帮我干什么」
- [ ] 界面上能看到过滤确实发生（收起区可展开、有原因）
- [ ] 计划书每条痛点后面都有实测数字，不出现「据调查」
- [ ] 能一句话说清「为什么知乎自己不做」（利益结构，不是技术）

### 维度二 · 创新度（25%）

**评委在找**：有没有一个别人没想到的点。

| 洞察 | 界面上的对应物 |
|---|---|
| 高赞 ≠ 可信 | 来源角标 + 降权原因，不按热度排序 |
| 改写查询本身就是过滤 | 技术抽屉里能看到「拆成了哪几个问题」 |
| **没料时不编**（新增） | 第三演示场景：材料不足就明说，不给假答案 |
| 允许推翻系统 | 「我认为这条没问题」，能点、有反馈 |

**验收检查项**

- [ ] 能一句话说出「我们和别人不一样的地方」
- [ ] 这个不同点**界面上看得见**，不是只有文档里有
- [ ] 至少一个设计是评委没见过的（建议：收起内容可推翻）
- [ ] 没有为了显厉害而存在的功能

### 维度三 · 完成度（25%）

**评委在试**：点下去会不会坏。最容易失分，也最没借口。

**验收检查项**

- [ ] 断网仍能打开并给提示，不白屏不崩
- [ ] 搜不到时空结果 + 可操作建议
- [ ] 全站搜不到 `alert(`，所有按钮都有真实行为
- [ ] 连点 10 次控制台无报错
- [ ] 375px 手机可用，无横向滚动
- [ ] 同 query 两次检索结果一致（缓存生效）

### 维度四 · 产品体验与设计感（10%）

权重最低，但最容易砸。

**验收检查项**

- [ ] 375px 无横向滚动
- [ ] 全站正文最小字号 **≥14px**
- [ ] 界面搜不到「可信度 0.62 / 四层过滤 / trace / 观点聚类」
- [ ] 结论在第一屏可见，不用滚动
- [ ] 对比度足够

**排期位置**：最后 2–3 天专门做。前提是后端只出 JSON 不出 HTML——现在满足。

## 七、执行原则

1. **契约先成文**：P1 不做完，B 不开始接
2. **每步有可验证产出**：阶段结束要能点开看，不是「写完了」
3. **先真后美**：功能与真数据优先，视觉留最后
4. **不新增功能**：主路径完成前不加新想法，有想法记入 `备选功能清单.md`
5. **可降级是底线**：任何依赖外部服务的环节都要有本地兜底
6. **每天 push**：三人协作，不 push 等于没做
