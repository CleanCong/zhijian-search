# 部署清单（阿里云 ECS · Ubuntu）

> 目标：把后端 + 前端一起放到公网，任何人打开链接都能真搜。
> 预计耗时：30–40 分钟（含装环境）。第一次做按顺序来，不要跳步。

---

## 零、买机器时选这三样

| 项 | 选什么 | 说明 |
|---|---|---|
| 地域 | **香港** | 大陆节点未备案会被拦 80/443；香港免备案 |
| 镜像 | **Ubuntu 22.04 / 24.04** | 别选 CentOS / Alibaba Cloud Linux |
| 规格 | 2核4G（2核2G 也够） | 14 天约 85 元 |

买完记下：**公网 IP**、**root 密码**。

## 一、安全组（买完第一件事）

在 ECS 控制台 → 安全组 → 入方向，加一条：

| 协议 | 端口 | 授权对象 |
|---|---|---|
| TCP | **8000** | 0.0.0.0/0 |

> 为什么不用 80：备案问题主要卡在 80/443，用 8000 没人管。
> 如果阿里云默认只开了 22，8000 必须手动加，否则外面打不开。

**验证**：浏览器打开 `http://你的IP:8000/`，现在应该超时（因为还没起服务）。能超时说明端口通了；如果立刻"拒绝连接"，说明安全组没生效。

## 四、装知乎 CLI ★ 最容易卡的一步

CLI 的安装脚本在 skill 包里，服务器上没有。**两种办法，先试 A。**

### 办法 A：把本地 skill 目录传上去（推荐）

在你**自己电脑**上执行（不是服务器）：

```bash
scp -r "C:/Users/可怜虫/.workbuddy/skills/zhihu" root@你的IP:/opt/zhihu-skill
```

然后在**服务器**上：

```bash
cd /opt/zhihu-skill && sh scripts/setup.sh
```

### 办法 B：直接下载二进制

```bash
curl -fsSL https://developer-cdn.zhihu.com/zhihu-cli/releases/stable/manifest.json -o /tmp/m.json
cat /tmp/m.json     # 从这里找 linux-amd64 的下载地址
```

然后把对应地址 curl 下来，解压放到 `/opt/zhihu-cli/zhihu-cli`，加执行权限。

### 验证（两种办法都要做这步）

```bash
export ZHIHU_ACCESS_SECRET=你的secret
/opt/zhihu-cli/zhihu-cli auth status
```

看到 `"source": "environment"` 就成了。

```bash
/opt/zhihu-cli/zhihu-cli search zhihu --query "测试" --count 1
```

看到 `"Code": 0` 就通了。

> **这一步失败就别往下走了。** 说明 Linux 二进制装不上，得改走 HTTP 直连方案（工作量大），或者退回内网穿透。

## 六、先手动跑一次（验证能通）

```bash
cd /opt/zhijian-search/backend
./run.sh
```

另开一个终端窗口，测试：

```bash
curl -s http://127.0.0.1:8000/           # 应该返回 {"ok": true, ...}
curl -s -X POST http://127.0.0.1:8000/api/search \
  -H "Content-Type: application/json" \
  -d '{"query":"全屋定制怎么避免被坑"}' | head -c 300
```

能返回内容就说明整条链路通了。

**然后去浏览器打开 `http://你的IP:8000/app/`** —— 应该能看到完整页面，而且能真搜。

> 到这一步如果就能搜，剩下的只是「让它别挂」。可以先发给队友看。

## 七、挂成常驻服务（挂了自动重启）

`Ctrl+C` 停掉刚才的进程，然后：

```bash
# 建一个专用用户（不用 root 跑服务）
useradd -r -s /bin/false zhijian

# 环境变量放到系统目录
cp /opt/zhijian-search/deploy/zhijian.env.example /etc/zhijian.env
nano /etc/zhijian.env      # 填入真实 secret 和 key
chmod 600 /etc/zhijian.env

# 装服务
cp /opt/zhijian-search/deploy/zhijian.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now zhijian

# 看状态
systemctl status zhijian
```

看到 `active (running)` 就成了。

**测试自动重启**：

```bash
pkill -f uvicorn
sleep 5
curl -s http://127.0.0.1:8000/     # 应该又活了
```

cd /opt/zhijian-search/backend

## 常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 浏览器打不开，一直转圈 | 安全组没开 8000 | 控制台加入方向规则 |
| 页面能开但顶栏是黄点 | 前端连不上后端 | 检查是不是从 `/app/` 访问的（同源才能连） |
| 搜索超时 | CLI 没装好或凭据不对 | 回到第四步验证 `Code:0` |
| 报 `address already in use` | 重复启动 | `pkill -f uvicorn` 再起 |
| 改了代码没生效 | 缓存或没重启 | `rm -rf _cache` + `systemctl restart zhijian` |
| 中文乱码 | 缺 locale | `apt install -y locales && locale-gen zh_CN.UTF-8` |

---

## 记住三件事

1. **不要用 80 端口** —— 备案问题
2. **先验证 CLI 能用，再折腾别的** —— 这是唯一可能走不通的环节
3. **演示前预热缓存** —— 否则评委同时点会撞限流

### 部署中实际踩到的两个坑

**① `requirements.txt` 漏了 `requests`**
`llm.py` 里 `import requests` 调 DeepSeek，但依赖清单里没有。本地因为全局装过所以一直没暴露，
新服务器上 `pip install -r` 之后启动直接报 `ModuleNotFoundError`。已补。

**② 前端后端地址推导错误**
原逻辑 `location.port === '8000' ? '' : ':8000'`，在页面本身就部署在 8000 端口时会把端口去掉，
拼出 `http://47.238.165.6`（默认 80），导致连不上、降级成演示数据、顶栏黄点。
改为直接用 `location.origin`。**这个 bug 在本地 file:// 下永远测不出来。**
