二、项目背景与目标

（一）一句话定位

知鉴Search 是一个基于知乎开放内容的 RAG 增强检索引擎，在普通检索之上叠加四层过滤与观点对照的「信息审校层」，不输出唯一标准答案，而是给出可信、不单边、可追溯的结果，并支持按需的增值加工（资料精选重组、科普视频）。

（二）赛事与赛道方向

本文档对应知乎黑客松 S3·湾区共创季赛道 01「AI × 知识与探索」（社区 × 知识发现）。

主攻方向为该赛道四条作品方向中的第二条——个性化知识发现、信息过滤、观点对照类 AI 应用原型。产品中的四层过滤对应其中的「信息过滤」，共识、分歧、风险三栏矩阵对应「观点对照」。

兼顾方向为第三条——依托知乎热榜、搜索、直答能力打造科普拆解、资料梳理助手，由增值功能（科普视频、精选重组）覆盖，不作为主路径。

（三）核心痛点

编号痛点说明
痛点1观点单边普通搜索或总结只给一种立场，用户看不到对立观点
痛点2长文难提炼优质经验散落在长回答里，缺核心结论、前提、踩坑的结构化呈现
痛点3软文泛滥带货洗稿混在真实经验里，难以辨别
痛点5信息过时老旧回答与当前情况脱节，缺时效提示

原始文档中痛点编号为 1、2、3、5，缺第 4 项。本次整理按原编号呈现、未作重排，是否存在遗漏项见第九章 A-01。

（四）产品目标

  1. 结果可信：不输出唯一标准答案，给出可信、不单边、可追溯的结果。
  2. 主路径秒出：提问即出整合好的答案，零操作。
  3. 增值可控：增值功能一律按需触发，不打扰快速用户。
  4. 可离线演示：默认 offline 模式，零 API 额度即可完整跑通全链路。

（五）设计原则

主路径永远秒出可用结果；增值功能一律按需触发，不打扰快速用户。

（三）检索与预处理

FR-1 Query 改写与意图识别（P0）

识别意图，分为对比选购、经验查询、争议话题、综合四类；将原始 query 拆成多个子查询以扩大召回、覆盖正反立场。

FR-2 多源召回（P0）

调用知乎搜索与问题下回答作为数据来源；默认走离线缓存 seed 数据集，以规避额度限制与现场演示风险。

（四）四层过滤

本节为产品的核心差异化能力，四条需求分别对应第三章列出的四类痛点。

FR-3 时效校验（P0，对应痛点5）

按 CreateTime 做时间衰减打分，标记「内容过时」；支持用户自定义时间窗（近 3 月 / 半年 / 1 年 / 不限），在本地完成过滤。

FR-4 可信度质检（P0，对应痛点3）

以 LLM 语义判断结合客观信号（赞同、评论、权威等级）做双因子打分；低可信度内容降权标红但不删除，保留给用户判断；必须输出判断理由。

FR-5 结构化萃取（P0，对应痛点2）

对同一问题的多条回答做摘要聚合，输出标准卡片，字段为核心结论、适用前提、优点、缺点、踩坑、风险，并附溯源链接。

FR-6 观点对照（P0，对应痛点1）

聚类成共识、分歧、风险三栏矩阵，不强行合并为单一答案；无真实分歧时留空并说明，禁止硬凑对立。

FR-7 综合重排（P0）

按相关性、可信度、时效三因子加权排序。

（五）结果呈现

FR-8 双视图（P0）

提供卡片视图（单问题结构化摘要）与矩阵视图（跨回答观点对照）两种呈现形态。

FR-9 风险标签（P0）

每条结果带可信度分、时效分，以及「内容过时」「疑似软文」标签。

FR-10 全程溯源（P0）

每条内容带可点击的知乎原文链接，确保有效不断链。

FR-11 链路可解释（P1）

展示检索链路 trace，包括改写、召回、各层过滤后的条目数量，体现处理过程的透明度。

（六）增值功能

FR-12 精选重组（P1）

每条要点、观点、回答带勾选框，粒度细到单条结论、优点、踩坑、观点；用户勾选后点「整合所选」生成定制资料；默认本地拼接（零额度），可选 LLM 润色成文；整合结果保留每条溯源链接与可信度、时效标签。

FR-13 科普视频（P2）

仅对「可拆解、有深度」的话题显示生成按钮；链路为脚本（LLM 分镜）、配图（逐镜头生图）、字幕，最终以 HTML 分镜播放器呈现；配音可选，采用浏览器朗读。

FR-14 导出（P1）

精选资料支持导出为 Markdown。

（七）诚实兜底

FR-15 低质量兜底（P0）

当召回质量差或全部为低可信内容时，显式告知用户「本次未找到高可信内容」，不强行拼凑答案；若使用 fallback 内容，须明确标注为「内置默认，非真实命中」。

（八）个性化配置

FR-16 过滤开关（P1）

用户可随时开关「过滤软文」「时效筛选」「观点矩阵」「结构化卡片」等能力。

FR-17 阈值可调（P1）

用户可手动调整过滤阈值，例如「只看可信度 > 0.7」。

五、主要业务流程

（一）主流程（快捷模式）

用户输入 query 后，系统按以下顺序处理，任一步的产物即为下一步输入。

步骤环节处理说明输出对应需求
1Query 改写与意图识别判定意图类型，拆为多个子查询子查询集合与意图标签FR-1
2多源召回缓存优先，不足时实时补充候选回答集合及元数据FR-2
3时效校验按 CreateTime 打分并按时间窗过滤带时效分与过时标记的候选集FR-3
4可信度质检LLM 语义判断加客观信号双因子带可信度分与判断理由的候选集FR-4
5综合重排相关性、可信度、时效加权排序后的结果集FR-7
6结构化萃取与观点对照按问题聚合生成卡片，跨回答聚类生成矩阵卡片集合与三栏矩阵FR-5、FR-6
7结果呈现双视图、风险标签、溯源链接、链路 trace结果页FR-8 至 FR-11
8兜底判定全程判断是否满足高可信条件正常结果或兜底提示FR-15

（二）增值流程一：精选重组

  1. 用户在结果页点击「自己挑重点重组」，进入精选模式。
  2. 系统在卡片与矩阵的每条要点、观点上提供勾选框。
  3. 用户勾选后点击「整合所选」，前端将勾选项提交至 POST /api/compose。
  4. 后端默认以本地拼接方式生成定制资料；用户可选择经 LLM 润色成文。
  5. 返回整合结果，每条内容保留溯源链接与可信度、时效标签。
  6. 用户可将结果导出为 Markdown。

（三）增值流程二：科普视频

  1. 仅当话题被判定为「可拆解、有深度」时，结果页显示「生成科普视频」按钮。
  2. 点击后提交至 POST /api/video，生成分镜脚本。
  3. 逐镜头配图并合成字幕。
  4. 以 HTML 分镜播放器呈现；配音可选，采用浏览器朗读。

（四）兜底分支

在召回质量差或全部内容为低可信时，主流程于结果呈现前转入兜底：输出「本次未找到高可信内容」的明确提示，不强行拼凑答案；若使用了 fallback 内容，须标注为「内置默认，非真实命中」。该分支的判定与呈现对应 FR-15。

（五）数据流总览

  1. 用户 Query。
  2. Query 改写与意图识别，产生多个子查询。
  3. 召回 topN，缓存优先。
  4. 时效打分与窗口过滤。
  5. 可信度质检，LLM 加客观信号，输出判断理由。
  6. BGE 重排与多因子综合排序。
  7. 结构化萃取生成卡片，观点聚类生成矩阵。
  8. 返回卡片、矩阵、风险标签、溯源链接与 trace。
  9. 可选：精选重组，调用 /api/compose。
  10. 可选：科普视频，输出 HTML 分镜。
  11. 兜底：无高可信内容时诚实告知。

为满足 NFR-1，seed 数据集需覆盖可支撑演示的若干主题，并包含上表所列全部字段，使四层过滤在离线状态下均可产生可见效果。数据规模与主题覆盖范围待确认，见第九章 A-08。

（四）技术约束与应对

原始文档记录的实测约束及对应处置方式如下，这些约束已直接影响了 FR-5 的实现深度与整体演示形态。

实测约束应对方式
搜索只返回摘要而非全文结构化萃取降级为「问题级摘要聚合」
额度极低（搜索 10 次/天、直答 2 次/天）默认离线缓存 seed；hybrid 模式下缓存优先、实时兜底

附录 A 呈现层约定

本附录收录原型设计评审中形成、与原始功能需求条目一一对应的呈现层要求。这些要求不新增功能，只约束既有需求在界面上的表达方式，来源与正文需求不同，故单列。

A-1 界面文案人话化（对应 FR-3、FR-4、FR-9）

界面不出现内部机制术语，包括「四层过滤」「结构化萃取」「观点聚类」「可信度质检」及具体分值。可信度以人话标签表达，例如「这条可能是软文」「这条是 2021 年的，情况可能变了」。

A-2 三层披露（对应 NFR-3）

同一判断按三层递进呈现：默认层给一句结论式提醒；悬停层给判断依据，例如「3 处商品链接、2 处亲测好用话术」；展开层给分数构成与链路数据。默认层面向全部用户，展开层面向需要核对的用户与评委。

A-3 技术细节开关（对应 FR-11、NFR-3）

链路 trace、可信度与时效分的计算构成收于一个默认关闭的「显示技术细节」开关内，不占主视觉区域。开启后展示完整数据，供演示时按需调用。

A-4 被降权内容可见、可展开、可推翻（对应 FR-4）

被降权的低可信内容不以直接删除或完全隐藏的方式处理，而以折叠区呈现，例如「另有 3 条疑似软文已收起，展开查看」。展开后每条须说明判定为低可信的理由，并允许用户手动标记「我认为这条没有问题」，使判断权回到用户。

A-5 矩阵三栏命名（对应 FR-6）

三栏在界面上以用户语言呈现，建议为「大家都同意」「说法不一」「有人踩过的坑」，替代内部术语共识、分歧、风险。数据分类逻辑不变。

A-6 流式过程的界面反馈（对应 NFR-2、NFR-5）

检索结果先行呈现后，卡片与矩阵异步补上的过程中，须提供骨架屏与分段进度反馈，不得以空白或单一转圈替代，避免演示时被误判为无响应。

附录 B 范围边界

本期包含：四层过滤检索、双视图、精选重组、诚实兜底、离线演示、科普视频（HTML 分镜形态）。

本期不含：真实 mp4 视频合成（当前环境无 ffmpeg 与视频渲染能力）、账号体系、多轮长期记忆、云端部署。
