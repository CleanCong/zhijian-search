------------------------------------------------------------
B0 · 守住一句话（全程）
------------------------------------------------------------
界面、文案、报错提示，全部围绕这一句：

  「把知乎上各说各话的二十篇经验，压成一张能下决定的卡片。」

出现以下词，立刻删掉：
  × 可信度 0.62 / 综合评分 / 四层过滤 / 观点聚类
  × trace / 链路 / 召回 / 重排 / 意图识别
  × 结构化萃取 / 信息审校层 / RAG

换成：
  √ 这条可能是软文，已收起
  √ 这条是 2021 年的，情况可能变了
  √ 从 40 条里挑了 24 条更可信的
  √ 12 个人里 9 个说好，3 个说踩坑

B1 · 读懂后端返回，定字段（D2）
------------------------------------------------------------
做什么：
  起后端（见 backend/README.md），用 /docs 或 curl 调一次
  POST /api/search，把真实返回打印出来看。

  关键字段（都在 pipeline.py 的 payload 里）：
    mode                real / degraded，决定显示模式标记
    intent_label        「对比选购」「经验避坑」这类
    answers[]           每条含 group / is_ad_suspect / reasons
                        / title / content_text / url / author_signature
                        / vote_up_count / age_days
    answers[].group     consensus / disputed / pitfalls / hidden
    cards[0]            core_conclusion / conclusion_confidence
                        / key_points / basis_titles / summary_source
    trace[]             各阶段的 label 和 detail，可直接读

产出：
  一页字段对照表（哪个字段渲染到界面哪个位置）

算完成：
  你能照着它写完全部渲染逻辑，不需要问后端

注意：
  · 后端只出 JSON，不出 HTML，所以改视觉不用动后端
  · conclusion_confidence 是 none 时，不要显示结论句，
    改显示 key_points 列表 + 一句「这条没法下结论，你自己看」
  · summary_source 是 rule 时说明模型没跑通，内容质量会差一档

------------------------------------------------------------
B2 · 接真数据（D3）
------------------------------------------------------------
做什么：
  把 data.js 里的假数据换成接口真实返回。
  保留一份 seed 数据（另存 data.seed.js）作为降级兜底。

算完成：
  界面显示真实知乎内容，渲染代码一行不用改

注意：
  · 渲染函数只依赖字段名，不依赖具体内容
  · 正文可能接近 1000 字，要考虑截断与展开
  · 后端一次要 4-6 秒，加载态必须有进度感，不能空白转圈

------------------------------------------------------------
B3 · 双模切换（D3）
------------------------------------------------------------
做什么：
  启动时请求后端，三种结果分别处理：
  1. 成功 → mode=real，顶栏显示「真实检索」
  2. 失败/超时 → 自动用 seed 数据，标「演示数据（后端未连接）」
  3. 后端返回 degraded → 同样显示降级标记 + degraded_reason

算完成：
  拔掉网线，页面仍能完整演示，有清楚提示，不白屏不报错

注意：
  · 标记必须诚实，不能假装是真实检索
    （官方检查第 9 条：不得把 Mock 写成最终交付）
  · 超时设 8 秒
  · 标记放顶栏状态区，不要做成警告条吓人

------------------------------------------------------------
B4 · 勾选重组 + 导出（D4）★ 优先级高于任何视觉调整
------------------------------------------------------------
做什么：
  1. 每条要点/结论/踩坑旁出现勾选框（一句话级，不是整条回答）
  2. 底部浮出「已选 N 条 · 整合所选」
  3. 点开是文档式版面，按主题分组，每条保留作者、年份、来源
  4. 「导出 Markdown」真的下载 .md 文件

算完成：
  勾 3 条 → 整合 → 导出 → 真的下载到文件，含来源与标签

注意：
  · 现在这两个按钮是 alert 占位，必须做成真的
  · 导出文件带免责说明：「本地拼接自检索结果，可信度与时效为系统辅助评估」
  · 这是 PRD 主推的增值项，也是「用户带得走的资产」，不要砍

------------------------------------------------------------
B5 · 降权区做透（D4）
------------------------------------------------------------
做什么：
  1. 底部一条折叠：「另有 13 条内容，我们觉得你不该直接信」
     数字来自 answers 里 group=hidden 的数量
  2. 展开后每条显示：
     - 为什么收起（用 reasons[]，一句人话）
     - 原文本身（照原样显示，不删不改）
     - 来源与年份
     - 按钮「我认为这条没问题」
  3. 点后变成「已记录你的判断 · 下次不再收起」

算完成：
  展开能看到软文原文和各自原因，按钮能点、有反馈

注意：
  · 这是整个产品最值钱的一块。它同时是：
    用户价值（能看到被过滤的东西）、评委价值（证明不是套壳）、
    主张证据（判断权归用户）
  · 不要做成「已屏蔽」的灰色态，要能正常读
  · 原因要具体：「文末有购买链接」比「疑似推广」有力十倍

------------------------------------------------------------
B6 · 状态矩阵（D5）
------------------------------------------------------------
做什么：
  六种状态都要有画面：
  1. 加载中 —— 4-6 秒，要有进度感（逐段点亮），不是空白转圈
  2. 空结果 —— 说明为什么没找到 + 两个可操作建议
  3. 接口失败 —— 明确提示 + 自动降级
  4. 额度耗尽 —— 说明并降级
  5. 材料不足（conclusion_confidence=none）—— 显示要点列表 + 老实说没结论
  6. 超长文本 —— 截断 + 展开

算完成：
  六种状态逐一截图，都能看到完整画面

注意：
  第 5 种是本产品独有的，不要藏起来。它恰恰证明「不硬凑」。
  官方检查第 7 条明文要求前四种都有真实提示。

B8 · 三个演示场景（D6）★ 场景已重新确定
------------------------------------------------------------
做什么：
  按这三个场景各跑一遍，确保都能演示：

  1. 主场景：全屋定制怎么避免被坑

     预期：材料不足，老实说「没法判断」

算完成：

注意：
  · 这三个组合是刻意设计的，不要换成三个都「有答案」的
  · 第 3 个场景是加分项：它证明系统在没料的时候不会编
